리뷰는 다음 순서로 진행한다.

1. 먼저 codex MCP의 review 툴(`/codex:review`)을 호출해서 리뷰를 수행한다.
2. 실패하면(rate limit / API 한도 초과, 또는 `openai-codex` 플러그인이 설치되어 있지 않아 `/codex:review` 자체가 없는 경우 포함):
   - 이유를 짧게 알리고("Codex 한도 초과로 직접 리뷰를 진행합니다" 또는 "codex 플러그인이 없어 직접 리뷰를 진행합니다") 넘어간다.
   - 이후 요청은 codex 없이 네가 직접 코드 리뷰를 수행한다.
   - 리뷰 기준: 버그 가능성, 보안 이슈, 코드 스타일/컨벤션, 테스트 커버리지.
3. codex 결과든 직접 리뷰든, 결과를 그대로 전달하고 끝내지 않는다 — 바로 이어서 타당성을 검토한다:
   - 지적된 파일:라인을 직접 읽어 사실관계를 확인한다.
   - 그 코드의 실제 호출부/소비자가 있는지 확인한다(`grep` 등) — 없으면 잠복 결함, 있으면 실사용 버그로 심각도를 가른다.
   - 지적이 틀렸거나 이미 해결된 것이면 그렇다고 명시한다 — 무비판적으로 승인하지 않는다.
4. 최종 결과는 아래 형식으로 정리한다.

## 리뷰 결과
- [심각도: High/Medium/Low] 이슈 설명 - 파일:라인

## 타당성 검토
- [지적 N] 사실확인: 맞음/틀림 · 소비자 유무: 있음(실사용 버그)/없음(잠복 결함) · 결론: 지금 고침/이월/기각(이유)
